Text Transfer v4 — optional lossless compression (app 1.4)

Try standard RFC1950 zlib-wrapped DEFLATE before CompactText15. Select v4 only
when its entire JSON envelope is shorter than the uncompressed v3 envelope.
Otherwise send v3 unchanged. v4 adds encoding="zlib" and packedSize (integer)
to the eight v3 fields. size/id/sha256 describe the ORIGINAL file, part=parts=1.
0 < packedSize < size < 1048576. Encode packedSize bytes with the alphabet below.
PC decodes exactly packedSize bytes, inflates with an original-size+1 output
bound, requires exact original size, stream EOF, no trailing data or second
stream, then verifies original SHA256. No raw DEFLATE, gzip or dictionaries.
Update APK and EXE together; older receivers cannot read v4.

Text Transfer v3 — CompactText15

No splitting. Same eight JSON fields, format=text-transfer-v3, part=parts=1.
size is original byte count (0 <= size < 1,048,576), id=sha256 full lowercase
SHA256 of original bytes, name is original filename.

Data alphabet (exactly 32768 printable BMP symbols):
  index     0.. 6581 -> U+3400..U+4DB5
  index  6582..27483 -> U+4E00..U+9FA5
  index 27484..32767 -> U+AC00..U+C0A3
Pack raw bytes in big-endian bit order, 15 bits per symbol. Final symbol pads
unused LOW bits with zero. Symbol count must be ceil(size*8/15). Decoder checks
padding, exact size, and SHA256. NFC is applied to v3 data before decoding to
handle decomposed Hangul. NFC/NFKC leave the canonical alphabet unchanged.
This is reversible encoding, not encryption or content compression.

Android copies the whole JSON using newPlainText, never a content URI.
App policy checks actual ClipData Parcel <=819200 bytes (800KiB), then writes
clipboard and reads it back as plain text before reporting confirmed success.
700KiB input produces about765KB UTF16 JSON before small Parcel overhead;
near1MiB input does NOT fit this policy. No claim of guaranteed Android maximum:
shared Binder buffer, keyboard policies and device conditions still apply.
Small email Intents include the body; large ones first copy normal text then
open a subject-only composer after user guidance. The user pastes once.
No attachments, OAuth, network permission, clipboard URI or automatic split.

PC reads v1/v2 legacy Base64, v3 CompactText15, and compressed v4. Formats may not be mixed in
one transfer. Update both APK and EXE; older EXE versions do not support v3.
