Base64 Transfer v2

Original file: 0 <= size < 1,048,576 bytes (1 MiB).
No splitting. Each file is exactly one JSON envelope:
{"format":"base64-transfer-v2","id":"<full lowercase SHA256>","name":"original.ext","size":123,"sha256":"<full lowercase SHA256>","part":1,"parts":1,"data":"<whole file standard padded Base64>"}

Decode the entire data field; verify original byte size and SHA256 before save.
The PC decoder also accepts legacy v1 independently encoded 100 KiB chunks.
Mixing v1 and v2 or files in the same transfer is rejected.

Android small payloads can be shared directly to Gmail body using Intent.
Large payloads: copy text using a read-only content URI backed by an app-owned
UTF-8 text stream, then launch Gmail WITHOUT body or attachments. The user
pastes once into the body. Clipboard text coercion support in the receiving
app is required. Actual Gmail device compatibility is NOT yet verified.
No OAuth account setup, network API, attachment, or automatic split is used.

Clipboard copy alone does not transmit text to a PC. Mail sending remains
explicit in Gmail. SHA256 detects corruption, not sender authenticity;
Base64 is not encryption.
