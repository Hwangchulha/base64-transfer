Base64 Transfer PC — 오프라인 파일 복원

요구 사항 / 실행
- Python 3.9 이상, 표준 라이브러리만 사용. GUI에는 tkinter/Tcl/Tk가 필요합니다.
- Windows: Python 설치 시 Tcl/Tk와 Python launcher를 포함한 뒤 launch.cmd 실행.
  launch.cmd는 자신의 폴더에서 py -3 app.py를 실행합니다.
- macOS/Linux: tkinter가 포함된 Python으로 python3 app.py 실행.
  Linux 배포판에서는 별도 python3-tk 패키지가 필요할 수 있습니다.
- 배포 묶음의 Base64Restore.exe는 Python 별도 설치 없이 실행됩니다.
  소스 실행 시에만 위 Python 설치가 필요합니다. 인터넷 연결은 필요하지 않습니다.

사용 방법
1. Android에서 복사하거나 이메일로 받은 완전한 JSON 조각을 준비합니다.
2. '클립보드 붙여넣기' 또는 텍스트 영역에 직접 붙여넣기 후 '조각 추가'.
   여러 JSON 객체를 연속해서 붙여넣어도 됩니다. 객체 사이 공백/줄바꿈 가능.
   이메일 제목, 서명, 코드 블록 표시 등은 제외하고 JSON 블록만 복사하세요.
3. 조각 순서는 자유이며 같은 조각을 다시 추가해도 중복 저장하지 않습니다.
   상태 줄에 누락된 조각 번호가 나옵니다. 추가 실패 시 해당 묶음 전체가 취소됩니다.
4. 모든 조각의 크기와 SHA-256 검증이 끝나면 '저장…'으로 위치를 선택합니다.
   기존 파일은 덮어쓰지 않습니다. 새 이름을 선택하세요. 취소하면 저장하지 않습니다.
5. 다른 파일을 받으려면 '초기화'. 입력 내용과 수신 조각이 모두 지워집니다.
   창을 닫으면 저장하지 않은 수신 내용은 사라집니다.

제약 / 파일 이름
- 원본은 0~1,048,575바이트. 빈 파일도 1개 조각입니다.
- 원시 조각은 102,400바이트(100 KiB), 마지막만 더 짧을 수 있으며 최대 11개입니다.
- format,id,name,size,sha256,part,parts,data의 정확한 8개 필드를 검사합니다.
  id와 sha256는 같은 소문자 SHA-256 전체 값이어야 합니다.
  정수 필드에는 boolean/실수를 허용하지 않습니다. 표준 패딩 Base64만 허용합니다.
- 추가 1회당 최대 2,097,152문자, 32개 객체. 이름 메타데이터 최대 1,024문자.
  크기, 조각 수/길이, 필드 유형, 중복 JSON 키, 손상/충돌을 검사합니다.
- 한 번에 파일 하나만 수신합니다. 서로 다른 ID 또는 메타데이터는 거부합니다.
- 원본 이름 메타데이터는 변경하지 않습니다. 저장 대화상자의 추천 이름만
  Windows/POSIX 경로를 제거하고 예약 장치명/금지 문자를 안전하게 바꿉니다.
  Unicode와 마지막 확장자를 유지하며 240 UTF-8바이트 이내로 줄입니다
  (UTF-16 240단위 이내도 충족). 확장자 자체가 239바이트를 넘으면 보존 불가.
  전체 경로 길이나 권한 등 OS 제약으로 저장에 실패할 수도 있습니다.
- 클립보드를 자동 감시하지 않습니다. 입력/수신 데이터는 메모리에만 보관합니다.
  저장 실패 시 새 경로에 불완전한 파일이 남을 수 있습니다.
- SHA-256은 손상 감지용이며 송신자 인증이나 암호화가 아닙니다.

검증 / Android 상호 운용
이 폴더에서 실행:
  python3 -m unittest -v
Windows에서는 python3 대신 py -3 사용.
테스트는 tkinter 없이 실행되며 경계값, 빈 파일, Unicode, 역순/중복,
누락, 충돌, 손상, 입력 제한, 안전한 추천 파일 이름을 검사합니다.

Android의 실제 envelope 출력을 UTF-8 텍스트 파일로 저장한 경우:
  python3 check_vectors.py part3.txt part1.txt part2.txt --expected original.bin
한 파일에 연속 JSON 객체를 넣어도 됩니다. 역순/중복 허용. 모든 조각이
필요하며 --expected는 선택 사항입니다. 복원 파일을 쓰지 않고 검사만 합니다.
테스트 벡터 형식은 프로토콜 JSON 자체이므로 별도 래퍼가 필요하지 않습니다.

Windows 11에서 EXE 빌드와 복원 단위 테스트 9개를 통과했습니다.
패키징된 EXE의 Tk 화면 초기화 및 디코더 자체 실행 검사도 통과했습니다.
실제 저장 대화상자와 사용자 클립보드 붙여넣기 조작은 수동 검증이 필요합니다.
